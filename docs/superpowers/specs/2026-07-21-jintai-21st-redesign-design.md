# 金泰 AI 全站 21st 改版设计规格

## 目标

把现有六页静态门户统一升级为“建筑级 AI 中枢”品牌体验：既有政企可信度，也有一眼可识别的空间叙事与视觉冲击力。保留现有公开内容边界、页面路由、静态导出和邮件咨询方式。

## 设计方向

- 视觉母题：一座可参观、可理解、可合作的 AI 基础设施大楼。
- 主色：深海军蓝；暖金只承担品牌定位、主操作和楼层坐标；石材白作为长内容区背景。
- 构图：大字号使命陈述、非对称网格、建筑线框、楼层编号和大面积留白。
- 排除项：紫粉 AI 渐变、粒子背景、夸张 3D 卡片、像素 Logo 墙、Emoji 图标和没有内容意义的装饰动效。

## 21st MCP 采用方式

- Modern Landing Hero（21st ID 18625）：复用其清晰的视觉层级、双 CTA 和下方展示面板结构；展示面板改为 AI 中心楼层剖面，不保留终端模拟器。
- Bento Product Features（21st ID 9206）：复用不等宽网格和内容槽位思想；使用原生 CSS/Tailwind 实现，不引入 Framer Motion，不使用外部头像或演示数据。
- Timeline-02（21st ID 5534）：参考其纵向节点结构，用于 AI 中心楼层与合作路径；不直接安装，保持当前依赖最小化。

## 全站信息架构

### 首页

1. 使命首屏：定位、价值主张、合作与参观双入口。
2. 信任依据：公开可表达的能力范围和交付方式，不使用虚构客户 Logo 或未经证实的数据。
3. 能力 Bento：算力基础、场景验证、内容交付与生态协同。
4. AI 中心楼层导览：用空间剖面解释能力如何在同一栋楼内协同。
5. 合作路径：业务咨询、预约参观、生态合作。
6. 咨询入口：低摩擦邮件表单和直接邮箱。

### 五个内页

- `/capabilities`：能力矩阵与交付边界。
- `/solutions`：按场景组织解决方案和合作起点。
- `/ai-center`：楼层导览、参观流程与空间叙事主页面。
- `/partners`：合作对象、合作方式与咨询入口。
- `/about`：金泰定位、原则和联系信息。

所有内页共享 Page Hero、章节编号、内容网格、底部 CTA 与页脚，形成统一识别。

## 组件与边界

- `SiteHeader`：桌面导航、移动菜单、当前页面状态和主 CTA。
- `PortalHero`：首页使命与建筑剖面可视化。
- `TrustStrip`：可信事实条，不展示不可验证指标。
- `AudiencePaths`：能力 Bento 网格。
- `CenterStory`：楼层导览与空间叙事。
- `CooperationPath`：三条合作路径与转化入口。
- `PageHero`：五个内页的统一首屏。
- `SectionHeading`、`FloorStack`、`SignalMark`：新增的轻量复用组件，只承载视觉一致性，不引入泛化框架。

## 交互与动效

- 主动效仅限首屏楼层线条、卡片进入和悬停反馈，每个视口最多 1 至 2 个明显动效。
- 动效时长 180 至 450 毫秒，不做滚动劫持和重度视差。
- `prefers-reduced-motion: reduce` 时停用位移、呼吸和循环动画。
- 所有交互目标不小于 44×44px，键盘焦点清晰可见，阅读顺序与 DOM 顺序一致。

## 响应式与性能

- 验证宽度：375、768、1024、1440px。
- 移动端楼层剖面退化为纵向卡片，Bento 退化为单列，不出现横向滚动。
- 不增加运行时动画库，不使用远程图片，不破坏 Next.js 静态导出或 GitHub Pages `basePath`。

## 测试与验收

- 更新结构测试，覆盖首页六段结构、全站共享 Hero/CTA、导航和公开内容边界。
- `npm test`、`npm run test:content`、`npm run lint`、根路径构建和 Pages `basePath` 构建全部通过。
- 浏览器逐页检查六条路由，在 375px 与 1440px 下确认无溢出、无不可读文本、无错误链接。
- 发布到现有 GitHub Pages 地址后再次逐页验证，并在浏览器中打开最终首页交付。
